# P45 与 Android 真机验证

**当前状态：源码实现已提供，P45 + Xiaomi 15／REDMI K Pad 组合尚未实机验收。** 本清单用于把设备枚举、输入、同步与记录逐项确认。自动构建和纯逻辑测试的结果单独记录。

## 接线与声音路径

P45 背面的 `USB TO HOST` 为 USB Type-B 接口。优先准备支持数据的 **USB-B 到 USB-C** 线；已有 USB-A 到 USB-B 线时，可加 USB-C OTG 主机转接。P45 使用自身电源适配器。

| 设备 | 首选连接 |
|---|---|
| Xiaomi 15 | Type-C，官方确认支持 OTG |
| REDMI K Pad | 短边 USB-C，官方明确标注 USB 2.0 HOST 数据传输 |
| Yamaha P45 | 背面 USB TO HOST（Type-B），数据传输使用 USB MIDI |

OpenMusic 接收的是琴键、力度和踏板等 MIDI 消息。P45 的 USB TO HOST 用于 MIDI，本应用对原始钢琴声音不做采集；听实际演奏请使用电钢琴扬声器或耳机，应用节拍和合成示范由 Android 输出。应用没有实现向 P45 发送示范音符。

初次测试使用 P45 普通单音色模式，避免 Dual 模式在两个 MIDI 通道上发送同一演奏；关闭电钢琴内置示范曲，直接手动按键。官方手册指出内置 Demo／Preset 曲目播放期间不输出演奏 MIDI。

官方依据：

- [Yamaha P45 使用手册，第 18 页](https://data.yamaha.com/files/download/other_assets/8/333228/P-45_owners_manual_En_D0.pdf)：USB 连接、AB 型线、MIDI 设置、Dual 与示范曲行为；建议 USB 线短于 3 米。
- [Yamaha P45 规格](https://usa.yamaha.com/musical-instruments/pianos/products/p-series/p-45/specs.html)：USB TO HOST、耳机与电源接口。
- [Xiaomi 15 接口与 OTG 官方 FAQ](https://www.mi.com/global/support/faq/details/KA-543988/)。
- [REDMI K Pad 官方参数](https://www.mi.com/prod/redmi-kpad/specs)：短边 USB-C 的 HOST 数据传输说明。
- [Android MIDI 官方文档](https://developer.android.com/reference/android/media/midi/package-summary)：Android MIDI 设备访问。

## A. 安装和离线基础功能

- [ ] 记录 APK 对应提交、设备型号、Android／HyperOS 版本。
- [ ] 安装 APK 后，曲库出现两份内置练习谱。
- [ ] 手机竖屏、横屏和平板横屏均能进入练习，底部播放按钮可见。
- [ ] 五线谱／简谱可以切换，音符与小节顺序相同。
- [ ] 示范模式能听到预备拍、节拍与合成音，游标按顺序移动。
- [ ] 导出示例 JSON，再从文件管理器导回；标题与小节数保持一致。
- [ ] 结构错误的 JSON 显示导入错误，已有曲库仍能使用。
- [ ] 切换后台后播放暂停，返回后可以继续。
- [ ] 其他应用取得音频焦点后练习暂停，返回应用可手动继续。
- [ ] 设备页展开测试键盘，按下／松开有可见反馈；随后关闭测试输入，再开始 MIDI 验证。

## B. USB MIDI 识别

- [ ] 给 P45 上电，通过数据线连接 Android。K Pad 首次使用短边接口。
- [ ] 打开「设备」，点击刷新；设备列表出现 Yamaha／Digital Piano 或系统提供的名称。
- [ ] 点击连接，状态显示已连接。
- [ ] 按中央 C 并松开，日志出现 Note On 与 Note Off 对应的字节；测试键盘关闭时 MIDI 输入生效。
- [ ] 连续重弹同一琴键、弹一个三和弦，再按几个黑键；每次起音都有对应日志。
- [ ] 轻按与重按产生不同 velocity；踩下与放开延音踏板可查看 CC64。
- [ ] 拔掉线材后状态更新；正在进行的练习保存为中断记录。
- [ ] 重插并重新连接后恢复输入。

日志使用原始十六进制 MIDI 字节。以通道 1 为例，`90 3C 40` 表示 MIDI 60（中央 C）以力度 64 起音，`80 3C 00` 或 `90 3C 00` 表示松键。`B0 40 7F` 是 CC64 踏板消息。通道不同会改变状态字节的低四位。

## C. 音高与节奏行为

- [ ] 选择基础样例、右手、A–B 第 1–2 小节，将速度降低。
- [ ] 「弹对前进」在目标音组等待；错误琴键显示提示，正确音组后继续。
- [ ] 同一琴键先松开再重弹，可匹配下一组相同音高。
- [ ] 在含片段尾部休止的谱中，最后目标匹配后仍等待尾休止；休止期间暂停再继续会保留剩余时间。
- [ ] 「跟拍练习」按预期速度前进；故意提前、延后和弹错，结果相应变化。
- [ ] 故意漏掉一个音，完整结束后出现漏音统计。
- [ ] 手动提前结束，记录标注中止原因；结果保留已发生部分。
- [ ] 切换到「测评」，过程中逐音反馈收起，结束结果仍显示检测统计。
- [ ] 关闭 MIDI 和测试键盘，用跟拍练习；界面显示检测未启用，结果只有用时。
- [ ] A–B 循环返回 A；每轮独立记录，持续音边界按片段重起／裁切。
- [ ] 切换左右手时目标和示范随之切换，谱面保留双手上下文。

## D. 时间偏移与长时间同步

先用设备扬声器进行校准，减少音频路径差异；后续更换输出设备时重新核对。设置中的「输入偏移」参与 `实际输入时间 − 目标时间 − 偏移` 的计算。稳定延迟时增加正偏移，稳定提前时使用负偏移；每次少量调整后重复同一短片段。

- [ ] 在固定音频输出和固定 BPM 下反复演奏短片段，记录调整前后的起音误差。
- [ ] 连续跟拍至少 5 分钟，观察谱面、节拍与示范是否逐渐分离。
- [ ] 预备拍结束的第一音、暂停续播后的第一音、循环返回的第一音均正确对齐。
- [ ] 最后一组起音仍能在完整匹配窗口内接收；出现「判分收尾」时，游标停在 B，结束后再生成本轮记录。
- [ ] 运行节奏样例，核对连音与反复后游标顺序。
- [ ] 导出 MIDI 日志与练习 JSON，确认输入来源、速度、片段、偏移及中断状态完整；`rawEvents` 包含通道、控制器值和排除暂停的用时，固定速度检测保存 `evaluationEvents`。

目前无法单靠 UI 判断残余的硬件输入／音频延迟。需要精确量化时，用外部录制或回环测量记录点击声与实际起音，再对照事件时间。

## 故障定位顺序

1. **无 MIDI 设备**：检查 P45 电源、数据线、Type-B 插头与 Android 主机端口。更换已确认能传输数据的线或 OTG 转接。
2. **设备能看到，连接失败**：关闭占用设备的其他 MIDI 应用，重插后刷新并连接。
3. **连接成功，按键没反应**：关闭测试键盘输入；直接手弹 P45，检查其单音色及 MIDI 发送设置，查看原始日志。
4. **同一音反复计作额外音**：检查 P45 Dual 模式；先用单音色复测，再查看日志中的 MIDI 通道。
5. **时间偏差始终一致**：固定音频输出路径后调整输入偏移。
6. **错误只在某首曲谱出现**：导出或保留 ScoreIR，检查音高、延音线、左右手谱表和演奏小节编号。

提交问题时附上提交版本、设备与系统版本、复现步骤、输入来源、练习参数、对应 ScoreIR，以及去除个人内容后的日志。曲谱中的可识别来源信息由导入者自行确认后再共享。
